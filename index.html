Assistant Cybersécurité — Logis Hôtel
Juin 2026 – Août 2026 (Stage en cours) Saint-Valery-sur-Somme PME hôtelière indépendante
Situation
Hôtel indépendant (1 PC Windows, PMS de réservation, Wi-Fi invités) sans équipe IT. Le SI n'avait jamais subi d'audit. Des données personnelles de clients (identité, carte bancaire, historique de séjours) étaient stockées sans politique de sécurité ni conformité RGPD.
Tâches — 6 missions
Mission 1 — IA appliquée à la sécurité : développement d'un script Python de classification automatique des emails entrants (analyse des entêtes, extraction des URL, comparaison avec la base VirusTotal API) pour bloquer les tentatives de phishing ciblant les hôtels.
Mission 2 — Audit réseau : vérification de la séparation Wi-Fi invités / réseau interne par scan Nmap depuis le réseau guest.
Mission 3 — Déploiement Wazuh : installation de l'agent Wazuh 4.7.0 sur le PC de réception Windows pour surveillance continue des événements de sécurité.
Mission 4 — Durcissement : mises à jour système (187 jours de retard), verrouillage automatique de session, politique de mots de passe renforcée, suppression des partages réseau non autorisés.
Mission 5 — Sensibilisation phishing : campagne de phishing simulé auprès des réceptionnistes et de la direction, avec exemples d'emails frauduleux hôteliers réels.
Mission 6 — RGPD : cartographie des traitements de données, rédaction fiche de traitement Art.30, politique de conservation remise à la direction.
Actions clés
Audit réseau : scan Nmap depuis Wi-Fi invités → 0 hosts up (segmentation confirmée). Scan interne PC réception → port 445/SMB ouvert. Get-SmbShare révèle un partage "Reservations" non déclaré contenant des données clients → supprimé avec Remove-SmbShare -Name "Reservations" -Force.

Déploiement agent Wazuh : installation via PowerShell sur le PC Windows de réception :
Invoke-WebRequest -Uri https://packages.wazuh.com/4.x/windows/wazuh-agent-4.7.0.msi -OutFile C:\wazuh-agent.msi
msiexec /i C:\wazuh-agent.msi WAZUH_MANAGER="192.168.1.10" /q
NET START WazuhSvc → The Wazuh Agent service was started successfully.

Alerte détectée : connexion à 02h34 hors horaires → investigation logs → faux positif (réceptionniste de nuit). Règle affinée pour exclure les plages nocturnes légitimes.

RGPD : 4 écarts identifiés — données de carte bancaire conservées après départ, historique clients sans durée définie, politique de mots de passe insuffisante, PC non verrouillé automatiquement. Fiche de traitement Art.30 rédigée et remise à la direction.
Résultats
Partage réseau "Reservations" supprimé 4 vulnérabilités identifiées et remediées Comptes admin : 5 → 2 Fiche RGPD Art.30 remise à la direction 2 emails suspects signalés post-formation Agent Wazuh opérationnel sur parc
« Chez Logis j'étais seul, sans équipe IT. La vraie faille était humaine — le PC jamais verrouillé, un partage réseau oublié contenant des données clients. Aucun outil ne corrige ça sans la sensibilisation. »

M6 — Interfaces sans code pour utilisateurs métier : développement de back-offices permettant à des utilisateurs non techniques de modifier textes, images et sections de sites clients sans intervention développeur.

M7 — Automatisation Python/Bash : 5+ scripts récurrents — vérification état des services, contrôle espace disque avec alerte email, rapports hebdomadaires SSH automatisés, réduisant les vérifications manuelles matinales.

Cybersécurité

Architecture

Résultat

Détection automatisée de EternalBlue (CVE-2017-0144, CVSS 9.8) sur des hôtes vulnérables. Rapport généré en quelques minutes vs plusieurs heures manuellement. API rate-limiting géré avec retry intelligent.

DevSecOps Pipeline — LogiStock
CI/CD sécurisé sur AWS avec 11 étapes de vérification
DevSecOps
Situation

Projet LogiStock (gestion de stocks Laravel 11) déployé sur AWS EC2 + RDS + S3. Besoin d'intégrer la sécurité à chaque étape du pipeline CI/CD pour garantir qu'aucun secret, vulnérabilité de code ou dépendance compromise ne passe en production.

Pipeline — 11 étapes GitHub Actions

Gitleaks : détection de secrets/clés dans les commits → Semgrep (SAST) : analyse statique du code PHP/Laravel → Bandit (Python) : détection patterns dangereux → Trivy (SCA) : scan des dépendances Composer et image Docker → Build Docker + push GHCR → Déploiement AWS via Ansible → Prometheus/Grafana pour monitoring post-déploiement.

Résultat

Pipeline bloque automatiquement tout commit contenant une faille critique avant qu'il n'atteigne la production. Rapport de sécurité généré à chaque PR.

Pipeline live — GitHub Actions
Voir le workflow sur GitHub
main.yml — Security CI/CD Pipeline (11 étapes) 
name: 🔐 Security Pipeline — LogiStock
on:
  push:    { branches: [main] }
  pull_request: { branches: [main] }

jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }

      - name: 🔑 Gitleaks — Secrets Detection
        uses: gitleaks/gitleaks-action@v2

      - name: 🔍 Semgrep — SAST PHP/Laravel
        uses: semgrep/semgrep-action@v1
        with:
          config: p/php p/laravel p/security-audit

      - name: 🐍 Bandit — Python Security Scan
        run: pip install bandit && bandit -r scripts/ -ll

      - name: 📦 Trivy — SCA Dependencies
        uses: aquasecurity/trivy-action@master
        with:
          scan-type: fs
          exit-code: 1
          severity: CRITICAL,HIGH

      - name: 🐳 Docker Build
        run: |
          docker build \
            -t ghcr.io/${{ github.repository }}:${{ github.sha }} .

      - name: 📤 Push to GHCR
        run: |
          echo ${{ secrets.GITHUB_TOKEN }} | docker login ghcr.io -u ${{ github.actor }} --password-stdin
          docker push ghcr.io/${{ github.repository }}:${{ github.sha }}

      - name: 🚀 Ansible Deploy — AWS EC2
        run: ansible-playbook -i inventory/prod deploy.yml
        env:
          ANSIBLE_HOST_KEY_CHECKING: 'false'

      - name: 📊 Prometheus Health Check
        run: curl -f http://${{ secrets.EC2_HOST }}:9090/-/healthy
